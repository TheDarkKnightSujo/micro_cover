# MicroCover demo walkthrough

Open the public root with `/#home` for the Overview screen. Existing links with `?guarantee=2` open that guarantee directly. All money is test USDC on Arc Testnet.

1. **Organiser/provider:** open For organisers, set the customer payment, extra failure compensation, maximum customers and deadlines. Review the fixed synthetic condition and evidence policy. Approve the exact bond, create the guarantee and share its link from My protection. The provider's bond is compensation times maximum customers; it is not collected from customers.
2. **Customer:** open the shared link, review payment/protection/terms, connect a separate test wallet and join with the existing exact approval + escrow payment flow. This is payment held in escrow, not an insurance premium sent immediately to the organiser.
3. **Outcome:** a demo operator uses the separate Demo controls to anchor and submit the prepared evidence result. Provider admission remains separate. Success requires the full existing review window; uncertainty retains its distinct fixed timeout. Those controls still enforce the original contract roles, confirmations and chain checks.
4. **Settlement:** existing permissionless payment actions live under Demo controls / Complete payments. Bond withdrawal stays provider-only. Read payment progress in the guarantee summary and Activity. Closed guarantees need no further claim.
5. **Activity:** readable entries explain the actions. Expand a receipt for its exact event, transaction link and stored Arkiv proof. Counts include public evidence-page entities that are not separate timeline events or charges. Hash agreement proves consistency with a commitment, not truth or collection completeness.

The concert ticket card on Overview is an illustration. Existing live guarantees have generic IDs and exact onchain terms. This UI does not add concert metadata, ticket inventory, real-world insurance underwriting, a premium product, independent evidence or native deployed CRE delivery. Both synthetic feeds remain controlled by us. Keep the laptop awake and online for the Quick Tunnel.

UI checks were performed with an isolated no-wallet headless Edge browser against the public HTTPS URL. They did not sign transactions or repeat the already settled financial scenarios. Studio reconciliation, user acceptance and the remaining Phase6 submission checks are pending. No commit/push was performed for this UI update.
