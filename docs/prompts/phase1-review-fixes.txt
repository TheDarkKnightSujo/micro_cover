Phase 1 draft review findings, independently reproduced locally against the initial Studio contract draft with Foundry 1.7.1/Solc 0.8.28. Fix in this same Studio project. Do not deploy/sign/broadcast/publish/commit. Preserve the Phase 1 scope and the full existing test suite.

1. Failure verdict uses failureAdmittedAt != 0 as a sentinel. A valid local execution at vm.warp(0), createGuarantee(5e6,2e6,1,100,200,bytes32(0)), admitFailure(id), returns Outcome.NONE even though status is FAILED. Record the verdict explicitly or derive it robustly from Phase 1 lifecycle so it never depends on time being nonzero. Add regression coverage at timestamp zero, after payout, and after closure.

2. _transferBatch and withdrawRemainingBond verify only sender balance deltas. A token can accept exact inbound amounts, then deduct a fee from the recipient while reducing the contract balance by exactly the requested amount. A locally tested toggled recipient-fee ERC20 paid only 6.3 out of a 7 USDC obligation, and settleFailure marked it paid. Require exact recipient amount receipt as well as correct sender debit (including provider leftover withdrawal), or otherwise preserve the obligation and revert atomically if exact payout cannot be established. Add tests that toggle recipient fees only after enrolling; ensure all state, previous transfers within the failing batch and accounting roll back. Official USDC remains the supported asset; do not assert general safety for arbitrary rebasing/malicious ERC20s.

The supplied review test is reference context, not an authoritative implementation or desired filename; integrate equivalent regression cases coherently without duplicating mock names. Rerun contract build/tests and bun run check, report real outcomes and remaining prototype limits. Do not drop or weaken a failing test to claim success.

3. Review UI read/error safety. In useGuarantee, a failed RPC read is currently labelled unknown guarantee; require decoded UnknownGuarantee before claiming that and display unavailable/unsupported reads distinctly. Do not silently treat failed membership or paid-flag reads as false or missing beneficiaries as an empty cohort. Disable dependent actions until necessary reads succeed; show retry/error. Keep supported viem/wagmi APIs.

AdmitSection has a two-click armed state which must not carry across selections/accounts; transaction results and cached membership must not be presented as another wallet/guarantee's. Make success callbacks once per confirmed transaction hash in useTxFlow.
